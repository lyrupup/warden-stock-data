## 1. 项目概述

### 1.1 项目简介

守望者行情数据服务（Warden Stock Data Service，下称「本服务」）是从 [`warden-stock-trading`](../../warden-stock-trading) 系统中**抽离行情数据能力**而独立出来的一套**行情数据中台服务**。

原 `warden-stock-trading` 把「行情数据 + 策略 + 持仓 + 风控 + AI 决策」耦合在一个系统里，其中「行情数据」是最底层、最通用、最值得被多方复用的能力。本服务的目标是把这块能力**单独沉淀为一个独立服务**，对外提供标准化的行情数据接口，让交易系统、量化回测系统、AI 投研系统等多个 Web/后端系统都能以统一方式接入。

本服务定位为「**数据眼睛**」（沿用守望者 **Scan · 侦查** 的能力代号）：持续侦查全市场行情，沉淀为高质量、可增量更新、可计算量化因子的行情数据底座。

### 1.2 与 `warden-stock-trading` 的关系

| 维度 | warden-stock-trading（原系统） | warden-stock-data（本服务） |
|------|------------------------------|----------------------------|
| 定位 | 面向个人投资者的交易决策系统 | 面向多系统的行情数据中台 |
| 行情能力 | 内嵌于 M1 模块，服务自身 | 独立服务，对外开放 API |
| 使用方 | 单一前端应用 | 多个外部应用（含原交易系统） |
| 鉴权 | JWT + 单用户默认放行 | 管理员 JWT（后台）+ secretId/secretKey（开放 API） |
| 数据源 | gotdx（直连通达信） | gotdx 起步，适配器模式可扩展多源 |
| 市场范围 | A 股 | A 股起步，预留 H 股 / 美股 |

> **复用与演进**：本服务的数据源适配层（`IMarketProvider` 抽象 + gotdx 连接池 + 字段映射）、行情模型（`StockQuote`/`IndexQuote`/`Kline`）、因子引擎（`MA`/`ma_align`/`bias` 等纯函数）均**直接迁移并增强**自原系统已验证的实现，避免重复造轮子。原系统后续可作为本服务的「第一个接入方」，通过 secretId/secretKey 读取行情，逐步把内嵌行情逻辑替换为远程调用。

### 1.3 产品定位

- **目标用户**：
  - **管理员**：本服务的运维者，负责数据源配置、更新调度、为接入方分发凭证。
  - **接入方应用（Consumer）**：通过 secretId/secretKey 接入、**只读消费**行情数据的其他系统（交易系统、量化系统、看板等）。
- **核心价值**：把分散在各系统中重复实现的行情拉取 / 缓存 / 落库 / 指标计算逻辑，收敛为一个**统一、可扩展、高性能**的行情数据中台。
- **平台形态**：后端 RESTful 行情数据服务 + 一个轻量 Web 管理后台（管理员登录、凭证分发、行情数据展示）。

### 1.4 文档目标与范围

本 PRD 明确**产品功能需求与边界**，作为后续输出《前端技术开发文档》《后端技术开发文档》《数据库设计文档》《接口设计文档》的唯一需求依据。本文档**不限定**具体实现细节（技术选型建议见第 7 章）。

**本期（V1）范围**：仅支持 **A 股**，数据源仅 **gotdx**，对外提供行情快照 / K 线 / 均线（MA5~MA60）等数据，支持增量更新与盘后定时批量更新，提供管理后台与开放 API 鉴权。H 股 / 美股、其他数据源、KDJ/MACD/RSI/BOLL 等指标**仅做架构预留与扩展点设计，不在本期实现**。

## 2. 名词术语表

| 术语 | 说明 |
|------|------|
| 行情数据中台 | 本服务，统一对外提供行情数据的后端服务 |
| 数据源（Provider / DataSource） | 行情原始数据的来源，如 gotdx（通达信）、Tushare、未来的港美股源 |
| 适配器（Adapter） | 屏蔽不同数据源差异、对齐统一接口的实现层 |
| 市场（Market） | 证券所属市场，如 A 股（CN）、港股（HK）、美股（US） |
| 指数行情（IndexQuote） | 大盘指数行情（上证指数、深证成指等） |
| 个股快照（StockQuote） | 个股的实时 / 准实时盘口快照（现价、涨跌幅、量额等） |
| K 线（Kline） | 日 / 周 / 月 / 分钟级的 OHLCV 序列 |
| 复权（Adjust） | 不复权(none) / 前复权(qfq) / 后复权(hfq) |
| 技术指标 / 量化因子 | 基于 K 线序列计算的派生数值，如 MA5、MA10、MACD、KDJ |
| 全市场扫描 | 对全市场所有标的逐只计算指标 / 匹配条件的批量作业 |
| 增量更新 | 仅拉取并写入「上次更新后新增 / 变化」的行情数据，避免全量重算 |
| 盘后批量更新 | 每个交易日收盘后某时间点触发的、自动分批全市场数据更新作业 |
| secretId / secretKey | 分发给接入方的开放 API 凭证对，用于身份与签名校验 |
| 接入方（Consumer） | 持有凭证、只读消费行情数据的外部应用 |
| 交易日历（TradingCalendar） | 标识哪些自然日是交易日，用于调度与增量判断 |

## 3. 用户、角色与权限模型

### 3.1 角色定义

| 角色 | 说明 | 主要载体 |
|------|------|---------|
| 管理员（Admin） | 本服务运维者：配置数据源、管理更新调度、分发与吊销接入凭证、查看行情与作业状态 | Web 管理后台（账号密码登录 + JWT） |
| 接入方应用（Consumer） | 持 secretId/secretKey 调用开放 API 的外部系统 | 开放 API（HTTP Header 凭证 / 签名） |

> **重要约束**：本服务**不面向 C 端个人用户**，没有「自选股」等个人维度业务（这些归属各接入方自身）。本服务只负责**公共行情数据**的生产与开放。

### 3.2 权限模型（核心约束）

| 能力 | Admin | Consumer |
|------|:-----:|:--------:|
| 管理后台登录 | ✅ | ❌ |
| 查看 / 配置数据源 | ✅ | ❌ |
| 触发 / 配置数据更新（增量 / 全量 / 调度） | ✅ | ❌ |
| 创建 / 吊销 / 查看 secretId-secretKey | ✅ | ❌ |
| **读取行情数据（快照 / K 线 / 指标 / 搜索）** | ✅ | ✅ |
| **写入 / 更新行情数据** | ✅（仅经更新作业） | ❌ |

> **铁律（对应需求 8）**：接入方通过 secretId/secretKey 接入后**只有数据读取权限，绝无任何数据写入 / 更新权限**。所有写操作（更新作业、调度配置、凭证管理）仅限管理员在后台触发，开放 API 不暴露任何写接口。权限边界在路由层（开放 API 路由组不挂载写路由）和鉴权中间件（凭证 scope 仅 `read`）双重保证。

### 3.3 多市场 / 多源数据归属

- 所有行情数据实体携带 `market` 字段（CN/HK/US），逻辑上按市场维度组织，为未来多市场预留（对应需求 2）。
- 所有行情数据可记录 `source` 字段（gotdx/tushare/...），标识数据来源，便于多源并存、对账与切换（对应需求 3）。

### M1 数据源适配与多市场接入模块

> 对应需求：**1（抽离行情逻辑）、2（多市场扩展）、3（多数据源适配器）**

#### 功能描述

本服务的「数据进口」。通过统一的行情数据源抽象接口，屏蔽底层不同数据源（gotdx / 未来 Tushare / 港美股源）与不同市场（A 股 / 未来 H 股 / 美股）的差异，向上层（M2/M3）提供**标准化、与数据源无关**的行情数据。本模块直接迁移并增强原 `warden-stock-trading` 中已验证的 `IMarketProvider` 适配层。

#### 核心功能点

- **F1.1 统一数据源接口（适配器模式）**：定义 `IMarketProvider` 接口，包含 `Indices`（指数）、`Quotes`（个股快照）、`Kline`（K 线）、`Search`（搜索）、`StockList`（全市场证券列表，新增）等方法。任何数据源以适配器形式实现该接口，上层只依赖接口，不依赖具体源。
- **F1.2 gotdx 适配器（A 股主力源）**：迁移原系统的 gotdx 直连实现：
  - **连接池**：gotdx 单连接非并发安全，使用「借出—独占—归还，异常即弃」的连接池（`max` 可配），并发拉取时复用。
  - **字段映射**：集中处理 gotdx 原始返回（价格 /100 或 /1000 还原为元、成交量「手」、换手率 /10000 还原为 %）到统一模型的转换。
  - **健壮性**：把 gotdx 解析层可能的 panic 转为 error，连接异常自动丢弃重建，不拖垮进程。
  - **证券名索引**：懒加载全市场「代码→名称/市场」索引，供搜索与名称补全复用。
- **F1.3 多市场抽象（扩展预留）**：行情模型与接口均带 `market` 维度（CN/HK/US）。V1 仅实现 CN（A 股）；H 股 / 美股以「新增对应市场的 Provider 适配器 + 市场路由」方式扩展，**不改动上层调用**。
- **F1.4 多数据源可插拔（扩展预留）**：通过工厂 `NewProvider(name, market, opts)` 按配置选择数据源实现；支持「主源 + 备源」降级链（如 gotdx 失败回退 Tushare），为未来多源对账预留接口。
- **F1.5 降级 Stub 源**：在无外部网络 / 无 gotdx 依赖时提供返回示例数据的 stub 适配器，保证服务可编译、可启动、可测试（迁移自原系统）。
- **F1.6 数据源健康检查**：暴露数据源连通性 / 延迟探测能力，供 M6 后台展示与告警。

#### 关键数据对象

- 数据源描述（DataSource）：source 标识、market、名称、状态（启用/禁用）、连接配置（连接池大小、超时、地址池等）、健康状态。
- 标准化行情模型（迁移自原系统，增加 `market`/`source` 字段）：
  - `IndexQuote`（指数行情）、`StockQuote`（个股快照）、`Kline`（K 线值对象）、`StockBrief`（搜索精简对象）。

#### 扩展性设计（重点）

```
上层(M2/M3/M4) ──仅依赖──► IMarketProvider (接口)
                               ▲
        ┌──────────────────────┼───────────────────────┐
        │                      │                        │
 ┌────────────┐        ┌──────────────┐         ┌────────────────┐
 │ gotdxProvider│       │[预留]tushare │         │[预留]HK/US源    │
 │  (CN, V1)   │        │  Provider    │         │   Provider     │
 └────────────┘        └──────────────┘         └────────────────┘
```

- 新增数据源 = 新增一个实现 `IMarketProvider` 的适配器 + 工厂注册，零侵入上层。
- 新增市场 = 在模型 `market` 维度下新增取值 + 对应市场的 Provider，路由层按 `market` 分发。

#### 验收要点

- 上层模块仅通过 `IMarketProvider` 取数，切换 / 新增数据源不需改动 M2/M3/M4 代码。
- gotdx 适配器能正确返回 A 股指数、个股快照、K 线、搜索结果，字段量纲正确。
- 无 gotdx / 无网络时服务可正常启动并以 stub 数据通过测试。
- 数据模型已带 `market`/`source` 字段，新增市场 / 数据源有明确扩展路径文档。

### M2 行情存储与增量更新调度模块

> 对应需求：**1（抽离）、4（性能优化 / 增量更新 / 全市场扫描 / 盘后定时分批批量更新）**

#### 功能描述

本服务的「数据底座」与「自动化引擎」。负责把 M1 拉取的行情数据**高效落库与缓存**，并提供**增量更新、全市场扫描计算、盘后定时分批批量更新**的能力，是性能优化与数据新鲜度的核心。

#### 核心功能点

- **F2.1 多级缓存取数链路**（迁移自原系统并增强）：读路径为「**Redis 缓存命中 → Provider 实时拉取 → PG 快照兜底（标记 stale 降级）**」，缓存命中场景常用查询 < 1s；TTL 可随交易时段动态调整（盘中短 TTL、盘后长 TTL）。
- **F2.2 行情数据持久化**：
  - 个股 / 指数**实时快照**落库（兜底降级用）。
  - 个股**日 K 线序列**落库（指标计算与全市场扫描的数据底座），支持前复权存储。
  - 全市场**证券列表**落库（代码、名称、市场、上市状态）。
- **F2.3 增量更新（核心性能优化）**：
  - 以「股票代码 + 交易日」为粒度记录每只标的的**最新已更新交易日水位（watermark）**。
  - 更新时仅拉取「水位之后的新增交易日 K 线」，避免全量重拉重算。
  - 实时快照按交易时段增量刷新（仅刷新被请求 / 被订阅的标的）。
- **F2.4 全市场扫描计算（核心能力）**：
  - 提供对**全市场所有标的逐只拉取 K 线 → 计算技术指标（调用 M3）→ 落库指标快照**的批量作业。
  - 解决原系统「全市场粗筛需个股指标快照表加速、尚未实现」的遗留问题：本服务以 `StockIndicatorSnapshot`（个股技术指标快照表，**以「股票 + 交易日」为粒度，每个历史交易日一行**）作为全市场扫描的加速底座。
  - **逐历史交易日指标快照（point-in-time，回测友好）**：扫描不仅算「最新交易日」的指标，还支持对**历史区间逐交易日**计算并落库指标快照（基于截止该日的 K 线序列计算，无未来函数）。这样接入方做量化回测时可**按交易日直接读历史指标**，无需每次重算。
  - 并发模型：信号量 channel 限流 + WaitGroup 同步（迁移自原系统粗筛引擎），单只标的失败不中断整轮，支持 context 取消 / 超时即时退出。
- **F2.5 盘后定时分批批量更新（对应需求 4 重点）**：
  - 支持配置**每个交易日收盘后的某个触发时间点**（如 15:30），自动启动全市场增量更新作业。
  - 作业**分批（batch）+ 限速（rate-limit）+ 限并发**执行，避免对数据源造成冲击、规避封禁。
  - **交易日历感知**：仅在交易日执行；非交易日自动跳过。
  - 作业可断点续跑、失败重试，记录每批进度与整体状态。
- **F2.6 更新作业管理**：管理员可手动触发（全量 / 增量 / 指定标的 / 指定市场）、暂停 / 恢复、查看进度与历史执行记录。
- **F2.7 数据新鲜度与水位查询**：可查询「全市场 / 某标的的数据更新到哪个交易日」「最近一次全市场扫描完成时间」，供 M4/M6 展示数据时效。

#### 关键数据对象

- 个股日 K 线（StockDailyKline）：market、source、stock_code、trade_date、OHLCV、复权口径。
- 行情快照（StockQuote / IndexQuote）：实时盘口快照（兜底降级用）。
- 个股技术指标快照（StockIndicatorSnapshot）：market、stock_code、trade_date、各指标值（MA5/10/20/30/60 等，JSONB 可扩展）—— **全市场扫描加速底座**。
- 更新水位（UpdateWatermark）：market、stock_code、last_updated_trade_date。
- 更新作业（UpdateJob）：类型（全量/增量/快照）、市场、范围、调度配置（cron / 触发时间点）、批次大小、并发度、状态。
- 作业执行记录（UpdateJobRun）：job_id、开始/结束时间、进度（已处理/总数）、成功/失败计数、状态、错误信息。
- 交易日历（TradingCalendar）：market、date、is_trading_day。

#### 扩展性设计

- 全市场扫描与盘后批量作业按 `market` 分市场调度，新增市场只需补充该市场交易日历 + Provider。
- 指标快照表以 JSONB 存指标值，新增指标（M3 扩展 KDJ/MACD 等）无需改表结构。

#### 验收要点

- 增量更新仅拉取水位之后的数据，全市场更新耗时与数据量显著优于全量重拉。
- 盘后到达配置时间点后，自动在交易日分批批量更新全市场数据，非交易日不执行。
- 全市场扫描能产出个股指标快照，供 M4 直接读取（无需实时重算）。
- 作业失败可重试 / 续跑，进度与日志可在 M6 后台查看。
- 缓存命中场景行情查询 < 1s；数据源异常时返回快照并标记 stale，不阻塞。

### M3 技术指标计算模块

> 对应需求：**5（输出 MA5/10/20/30/60，可扩展 KDJ/MACD/RSI/BOLL）**

#### 功能描述

本服务的「数据加工」。基于个股 K 线序列计算技术指标 / 量化因子，对外输出标准化指标数据，供接入方做量化因子使用。直接迁移并扩展原系统已验证的 `factor` 因子引擎（纯函数、可单测）。

#### 因子能力归属边界（重要约束）

「因子引擎」必须拆成两层，归属不同方，判断原则是 **「算什么」放本服务，「怎么用」放接入方**：

| 层 | 内容 | 归属 | 说明 |
|----|------|------|------|
| **因子计算层（`factor` / indicator）** | 给定 K 线序列 → 算出 MA5/10/20/30/60、bias、振幅、量比等**确定性数值**（含 `ma_align`/`amplitude_streak` 等布尔型因子） | ✅ **本服务（M3）** | 纯数据加工、无业务语义、口径唯一、可全市场盘后预计算落库、多方复用——是中台核心价值 |
| **因子组合 / 策略层（`rule` + 选股 + 回测撮合）** | 把因子用 `and/or`、`MA5>MA10` 等**组合成选股 / 买卖条件**并据此回测、下单 | ❌ **接入方** | 各家差异化、机密、频繁调参的业务策略；放中台会污染通用性 |

约束细则：

- 本服务对外**只暴露因子数值**（`/open/v1/indicators`、`/open/v1/stocks/{code}/indicators`），**不提供** 选股规则求值 / 策略存储 / 回测接口。
- 原系统的 `rule` 规则组合引擎**不进本服务对外 API**；如接入方需要，可将其作为**可移植代码库**自行复用，但「策略定义 + 组合判断 + 撮合回测」一律在接入方实现。
- 即使是带"判断"语义的布尔因子（`ma_align` 均线多头排列、`amplitude_streak` 连续振幅），因其为**确定性计算**（序列 → true/false），仍归因子计算层、留在本服务。真正的业务边界是「把这些因子用 and/or 拼成决策」。

#### 核心功能点

- **F3.1 均线指标（V1 必交付）**：输出 **MA5、MA10、MA20、MA30、MA60**（基于前复权日 K 线收盘价的简单移动均线），周期可参数化扩展（如 MA120/MA250）。
- **F3.2 已有因子迁移**：迁移原系统因子引擎，开箱即用：
  - `ma`（移动均线）、`ma_align`（均线多头/空头排列）、`bias`（乖离率）、`amplitude`（当日振幅）、`amplitude_streak`（连续振幅）、`pct_change`（N 日涨跌幅）、`field`（原始字段）、`vol_ratio`（量比）、`const`（常量）。
- **F3.3 指标计算口径统一**：所有指标基于「升序前复权日 K 线序列，最后一根为当前 bar」计算，口径与公式明确、纯函数、可单测覆盖。
- **F3.4 指标目录（Catalog）**：提供可扩展的指标元数据目录（类型、参数、单位、说明），作为「指标定义 ↔ 计算引擎 ↔ 前端展示」共用的单一事实源（迁移自原系统 catalog）。
- **F3.5 指标扩展点（KDJ/MACD/RSI/BOLL 预留）**：定义统一的指标计算注册机制 `Indicator` 接口（输入 K 线序列 + 参数，输出指标序列 / 当前值），新增指标 = 实现接口 + 注册到目录，不改动 M2/M4。本期**预留接口与目录占位，不实现**。
- **F3.6 两种计算时机**：
  - **离线批量**：由 M2 全市场扫描在盘后批量算好，落 `StockIndicatorSnapshot`（默认，供高并发只读）。
  - **实时计算**：对单只标的按需实时计算（拉 K 线即时算），用于明细页与未入快照的标的。

#### 关键数据对象

- 指标值（IndicatorValue）：指标类型、参数、数值 / 布尔值、所属 trade_date。
- 指标目录项（IndicatorCatalogItem）：type、name、value_type、unit、params（只读元数据）。
- 个股指标快照（StockIndicatorSnapshot，见 M2）：承载批量算好的指标值。

#### 扩展性设计

```
Indicator 接口: Compute(series Kline[], params) -> []IndicatorValue
   ├── MAIndicator        (V1 实现: MA5/10/20/30/60)
   ├── BiasIndicator      (V1 实现, 迁移)
   ├── ...                (其余迁移因子)
   ├── [预留] MACDIndicator
   ├── [预留] KDJIndicator
   ├── [预留] RSIIndicator
   └── [预留] BOLLIndicator
```

#### 验收要点

- 接口可返回任意个股的 MA5/MA10/MA20/MA30/MA60，数值与公式一致并经单测覆盖。
- 指标目录可被 M4/M6 读取，新增指标有明确接入路径（实现接口 + 注册）。
- 离线快照与实时计算两种路径结果一致。

#### 回测数据支撑边界（重要说明）

本服务定位为**只读行情数据中台**，对量化回测的支撑**仅限「数据层 + 因子层」**，不实现完整回测引擎：

- **本服务负责（已支持 / 本期增强）**：高质量历史 K 线（5 年、前复权、可按 `from`/`to` 区间查询）、技术因子计算、**逐历史交易日的指标快照（point-in-time，无未来函数）**。接入方可据此按日读历史 K 线与历史指标，完成回测所需的「信号生成」。
- **本服务不负责（留给接入方实现）**：撮合成交（手续费 / 税费 / 滑点 / 涨跌停停牌不可成交）、资金账户与持仓盯市推进、绩效指标（收益率 / 最大回撤 / 夏普 / 胜率）、回测任务调度与结果存储。这些属于业务策略逻辑，应放在接入方（如交易系统 / 专门的量化系统）。

> 即：本服务把「干净、可按日回放的历史数据与指标」喂给接入方，回测引擎在接入方拼装。如未来需在本服务内置回测引擎，再单列模块扩展。

### M4 行情数据开放 API 模块

> 对应需求：**5（指标输出）、6（secretId/secretKey 接入）、8（只读权限）**

#### 功能描述

本服务的「数据出口」。面向接入方应用提供一组**纯只读**的标准化行情数据 HTTP 接口，所有接口经 M5 凭证校验，**不提供任何写 / 更新接口**。

#### 核心功能点

- **F4.1 大盘指数行情**：返回当日大盘核心指数（上证指数、深证成指、创业板指、科创 50、沪深 300 等）。
- **F4.2 个股实时快照**：按代码（支持批量）返回个股盘口快照（现价、涨跌幅、开高低收、量额、换手率），命中缓存 < 1s，源异常时返回快照并标记 stale。
- **F4.3 个股 K 线**：返回个股日 / 周 / 月 / 分钟 K 线，支持复权口径（none/qfq/hfq）参数；支持 `limit`（最近 N 根）与 **`from`/`to` 交易日区间查询**（回测取历史区间用）。
- **F4.4 技术指标查询（核心）**：按代码返回 MA5/MA10/MA20/MA30/MA60 等指标值；支持「单只实时」与「批量读快照」两种模式；预留指标类型参数（未来 KDJ/MACD 等）。
- **F4.5 股票搜索**：按代码 / 名称关键字搜索标的，返回精简列表。
- **F4.6 证券列表 / 元数据**：返回全市场证券列表、交易日历、数据新鲜度（数据更新到哪个交易日）、支持的市场 / 指标目录等元信息。
- **F4.7 统一响应规范**：统一的成功 / 错误响应结构、错误码、分页约定；所有接口支持 context 超时中断。
- **F4.8 市场维度参数**：接口统一支持 `market` 参数（V1 默认 / 仅 CN），为多市场预留。

#### 接口分组（示意，最终以 openapi.yaml 为准）

```
GET  /open/v1/indices                      大盘指数
GET  /open/v1/quotes?codes=...             个股快照(批量)
GET  /open/v1/stocks/{code}                个股快照(单只)
GET  /open/v1/stocks/{code}/kline          个股 K 线
GET  /open/v1/stocks/{code}/indicators     个股指标(MA5~MA60...)
GET  /open/v1/indicators?codes=...         批量指标(读快照)
GET  /open/v1/search?kw=...                股票搜索
GET  /open/v1/securities                   证券列表
GET  /open/v1/meta                         市场/指标目录/数据新鲜度
（注：开放 API 路由组下不存在任何 POST/PUT/DELETE 写接口）
```

#### 关键数据对象

- 沿用 M1/M3 标准化模型（IndexQuote / StockQuote / Kline / IndicatorValue / StockBrief）的对外 DTO。
- 接入凭证上下文（由 M5 注入：consumer_id、scope=read、限流配额）。

#### 验收要点

- 所有开放接口均需有效 secretId/secretKey 才能调用，缺失 / 非法 / 吊销返回标准鉴权错误。
- 开放 API **不存在任何写接口**（路由层可验证）。
- 指标接口能正确输出 MA5/10/20/30/60。
- 缓存命中场景响应 < 1s；源异常降级返回 stale 数据不阻塞。

### M5 鉴权与凭证管理模块

> 对应需求：**6（secretId/secretKey 校验）、7（管理员分发凭证）、8（接入方只读）**

#### 功能描述

本服务的「安全网关」。提供两套鉴权体系：管理员后台的账号密码 + JWT 鉴权；开放 API 的 secretId/secretKey 凭证校验。并通过权限 scope 严格保证接入方**只读**。

#### 核心功能点

- **F5.1 管理员认证**：账号密码登录，签发 JWT；后台接口经 JWT 中间件鉴权；密码加盐哈希存储。预留多管理员与角色扩展。
- **F5.2 凭证生成与分发**：管理员可为接入方创建凭证对：
  - `secretId`（公开标识）+ `secretKey`（私密密钥，**仅创建时明文返回一次，落库仅存哈希**）。
  - 凭证可配置：名称 / 备注（标识接入方）、scope（V1 固定 `read`）、限流配额（QPS / 日调用上限）、有效期、状态（启用/吊销）。
- **F5.3 凭证校验中间件**：开放 API 经凭证校验中间件：
  - 校验方式 V1 支持 **Header 直传**（`X-Secret-Id` + `X-Secret-Key`）；预留**签名校验**（HMAC：secretId + 时间戳 + nonce + 请求摘要，用 secretKey 签名，防重放）作为更安全的接入方式。
  - 校验通过后注入 consumer 上下文（consumer_id、scope）。
- **F5.4 只读授权（铁律）**：凭证 scope V1 固定为 `read`；开放 API 路由组**仅注册读路由**，鉴权中间件拒绝任何非 `read` 操作。即使未来扩展 scope，写能力默认关闭。
- **F5.5 凭证级限流与配额**：按凭证维度限流（QPS）与日调用配额，超限返回 429；与全局限流中间件叠加。
- **F5.6 凭证生命周期管理**：管理员可吊销 / 重置（轮换）凭证；吊销后立即失效；保留调用审计。
- **F5.7 调用审计**：记录每个凭证的调用量、最近调用时间、错误率，供 M6 展示与风控。

#### 关键数据对象

- 管理员（Admin）：用户名、密码哈希、状态、角色（预留）。
- 接入凭证（ApiCredential）：secret_id、secret_key_hash、consumer_name、scope、rate_limit、daily_quota、status、expire_at、created_by、created_at。
- 凭证调用审计（CredentialAccessLog / 计数）：credential_id、调用计数、最近调用时间、错误计数。

#### 扩展性设计

- scope 设计为可扩展集合（V1 仅 `read`），未来若开放细粒度授权（如某接入方仅可读某市场 / 某指标）可平滑扩展。
- 校验方式从「Header 直传」平滑升级到「HMAC 签名」，中间件可按凭证配置选择校验策略。

#### 验收要点

- 管理员能登录后台并签发 JWT；后台接口未登录被拒。
- 管理员能创建凭证，secretKey 仅创建时明文返回一次，库内仅存哈希。
- 开放 API 无凭证 / 凭证错误 / 已吊销均被拒绝；凭证 scope 非 read 无法写。
- 凭证级限流 / 配额生效，超限返回 429。
- 吊销凭证后立即失效。

## 6. 非功能性需求

| 类别 | 需求说明 |
|------|---------|
| 性能 | 行情常用只读接口缓存命中 < 1s；全市场增量更新显著快于全量；全市场扫描支持高并发限流 |
| 安全性 | secretKey 仅哈希存储、仅创建时明文返回一次；管理员密码加盐哈希；开放 API 严格只读；防 XSS/CSRF/SQL 注入；预留 HMAC 签名防重放 |
| 权限隔离 | 接入方只读、零写权限；写操作仅管理员后台；路由层 + 中间件双重保证 |
| 可扩展性 | 数据源（适配器）、市场（CN/HK/US）、技术指标（KDJ/MACD/RSI/BOLL）均预留零侵入扩展点 |
| 可用性 | 数据源异常时降级返回快照并标记 stale，不阻塞；作业失败可重试 / 续跑 |
| 可观测性 | 更新作业、调用审计有日志与指标；作业可追踪进度、可重试、可手动触发 |
| 限流 / 配额 | 全局限流 + 凭证级限流与日配额；超限 429 |
| 数据合规 | 行情数据来源合法合规；对外仅提供公共行情数据，不含个人投资数据 |
| 兼容性 | 后端提供标准 RESTful API；前端主流现代浏览器、响应式（PC 优先） |
| 可维护性 | 前后端分离；分层解耦（adapter/service/repository/handler）；配置经环境变量注入，不硬编码 |
| 国际化 | 预留 i18n（V1 以中文为主），多市场命名预留多语言 |

> ⚠️ 免责：本服务仅提供行情数据，不构成投资建议；数据可能因数据源延迟 / 异常而存在偏差（以 stale 标记提示）。

## 7. 技术方案建议（非强制，供技术文档参考）

> 遵循项目 `AGENTS.md` 技术选型规范，与原 `warden-stock-trading` 保持一致以便迁移复用。

- **整体架构**：前后端分离，B/S；后端提供 RESTful API（管理 API + 开放 API 两套路由组）。
- **后端**：Go + Gin + GORM 作为核心行情服务；中间件含限流、超时（context 传播）、CORS、日志、Recovery、双鉴权（Admin JWT / 凭证校验）。采用 **TDD**（因子引擎、增量水位、凭证校验先写测试）。
- **数据源集成**：`IMarketProvider` 适配器抽象；A 股主力 gotdx（连接池 + `-tags gotdx` 构建注入，默认回退 stub）；预留 Tushare / 港美股源。
- **数据存储**：PostgreSQL（K 线 / 快照 / 指标快照 / 凭证 / 作业 / 交易日历）+ Redis（行情缓存 / 限流 / 配额计数 / 会话）。
- **任务调度**：内置 cron 调度器，盘后定时触发全市场分批增量更新；交易日历感知；作业记录与重试。可选 RabbitMQ 做大规模异步分批。
- **前端**：React + Vite + shadcn/ui + Tailwind CSS；请求 ky + TanStack Query；状态 zustand；K 线 / 指标图表；Light/Dark 主题。
- **基础设施**：PostgreSQL / Redis（可选 RabbitMQ）通过 Docker + docker-compose 编排；配置经环境变量注入。
- **目录规范**：遵循 `core/`（可移植：adapter / indicator / 缓存）与 `features/`（业务模块）划分；具名导出；类型前缀（T/E/I）。

## 8. 数据模型概览（逻辑层）

> 仅为逻辑实体概览，物理表结构详见后续《数据库设计文档》。公共行情数据不归属用户，凭证 / 管理数据归属管理体系。

```
公共行情数据（按 market / source 维度组织）
 ├─ DataSource(数据源配置)
 ├─ Security(证券列表: code/name/market/status)
 ├─ TradingCalendar(交易日历: market/date/is_trading_day)
 ├─ IndexQuote(指数行情快照)
 ├─ StockQuote(个股实时快照, 兜底降级)
 ├─ StockDailyKline(个股日 K 线序列, 复权)
 ├─ StockIndicatorSnapshot(个股技术指标快照: MA5/10/20/30/60..., JSONB 可扩展)
 ├─ UpdateWatermark(更新水位: market/code/last_trade_date)
 ├─ UpdateJob(更新作业: 类型/调度/批次/并发)
 └─ UpdateJobRun(作业执行记录: 进度/状态/错误)

管理与安全
 ├─ Admin(管理员: 账号/密码哈希/角色)
 ├─ ApiCredential(接入凭证: secret_id/secret_key_hash/scope=read/限流/配额/状态/有效期)
 └─ CredentialAccessLog(凭证调用审计: 调用量/最近调用/错误率)
```

### 11.2 关键决策（已确认）
1. **开放 API 校验方式**：V1 直接采用 **HMAC 签名校验**（secretId + 时间戳 + nonce + 请求摘要，用 secretKey 签名，防重放），不走 Header 明文直传。
2. **盘后定时更新默认参数**：默认触发时间点 **17:00（下午 5 点）**；默认**分批大小 20**；默认**并发度 10**。均可在后台配置覆盖。
3. **全市场扫描默认指标**：V1 默认仅计算 **MA 指标（MA5/MA10/MA20/MA30/MA60）**；其余迁移因子 / KDJ/MACD 等后续按需开启。
4. **交易日历数据来源**：**自维护交易日历表为主 + gotdx 拉取的实际 K 线日期反推校正**（自维护表按年导入交易所休市安排，K 线实际成交日交叉校验补漏）。
5. **K 线首次全量回补范围**：首次全量回补 **5 年**日 K 线。
